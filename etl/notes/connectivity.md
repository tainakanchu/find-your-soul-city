# World connectivity (non-stop destinations): source evaluation, not implemented

Quiz question: 「直行便でいろんな国・都市に行ける街がいい？」 (higher is better).
Intended metric: number of distinct foreign countries (and destination airports) served non-stop by scheduled
passenger flights from the airports serving each GHS-UCDB R2024A urban centre.

**Status (2026-10-29): not implemented.** No source passed all three checks (documented open access route,
open licence, current (≤ ~3 years) and global). No `connectivity.py`, interim JSON or reference CSV was produced.
The one promising route (Wikipedia destination tables) hit HTTP 429 on its first request and was stopped per the
external-access policy (see "Incident").

## Incident: Wikimedia API 429 (stopped, not retried)

- 2026-10-29 03:22:47 UTC: one single request,
  `GET https://en.wikipedia.org/w/api.php?action=parse&page=Heathrow_Airport&prop=wikitext&format=json&formatversion=2&maxlag=5&redirects=1`,
  with an identifying User-Agent. This was the first request to Wikimedia in this task.
- The response was HTTP 429: "You are making too many requests to the API. Please follow the best practices at
  https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits." (request-id 0711fdab-416b-4a65-99cb-d9e7d03ba154).
  The shared egress IP is probably already rate-limited.
- Per the external-access policy (rule 3), no retry was made and the Wikimedia route was abandoned. Switching to
  dumps.wikimedia.org (same provider, large downloads: the multistream index plus byte-range reads of about 300 pages)
  was **not** attempted without the user's decision.

## Diagnostic numbers (OpenFlights 2014 + OurAirports 2026-10-29; evaluation only, not published)

Computed in a scratch script and not part of the ETL. The method was the one intended for implementation:

- Airports = OurAirports `scheduled_service=yes`, type large/medium, with an IATA code (3,245 airports, 1,152 large).
- An airport serves a city if it lies within 50 km of the polygon edge (local equirectangular km).
- Count non-stop routes (`stops=0`), with destinations reduced to distinct destination countries other than the
  countries of the serving airports.

Inputs used: `airports.csv` sha256 f508467c…81ea, `routes.dat` sha256 bd373706…2390.

- Top: Paris 109, London 98, Istanbul 90, Dubai 86, Amsterdam 81, New York 73, Rome 68, Doha 62, Milan 60,
  Munich 60. Tokyo 40, Seoul 44, Singapore 38.
- Bottom: Fortaleza 4, Phoenix 3, Berlin, Ulaanbaatar, Dakar and Phnom Penh 0 (closed airports, see above).
- Spearman(log population, foreign countries) = 0.16 across the 130 cities. This is not just a city-size proxy;
  it reflects hub status and the small-country density of Europe.
- Buffer effects to handle in any future implementation:
  - A 50 km buffer crosses borders: Singapore picks up Batam (BTH, Indonesia) and Johor (JHB, Malaysia).
  - Dubai picks up Ras Al Khaimah (RKT, 40 km) and Sharjah.
  - Tokyo picks up Ibaraki (IBR, 41 km).
  - London gets 6 airports, New York 7.
  - No airport is shared between two of the 130 targets at 50 km. Sharing would happen in the 524-centre reference
    set (e.g. Randstad, Rhine-Ruhr).
  - A future implementation should report the serving airport list per city and probably weight or cap by
    distance, or restrict to the home country.

## Recommendation

1. Preferred: the user decides whether to use **Wikipedia destination tables via the monthly enwiki dump**
   (documented bulk route; CC BY-SA 4.0 attribution and share-alike; label `estimated`).
   - Only about 300 airport pages are needed: use `pages-articles-multistream-index` to locate them, then a few
     sequential byte-range reads.
   - Alternatively, retry the Action API later from a non-rate-limited IP, following the Wikimedia rate-limit
     guidance.
   - Validate against Eurostat `avia_par_*` (European cities, 2024) and BTS T-100 (US cities).
2. Fallback without routes: OurAirports alone gives a current, public-domain "airport supply" proxy, e.g. the number
   of scheduled large airports within 50 km. It is weak: it measures airport count, not destination breadth, and
   gets close to city size. It is not recommended for this question.
3. Do not use OpenFlights 2014 even as a fallback: closed or renamed airports produce false zeros (Berlin) and
   wrong attributions (IST).
